Your LP positions, read from the chain.

Type an address, or connect a wallet just long enough for this page to learn which address it is. Everything below is read from the Uniswap V3 position manager over public JSON-RPC. Anything this page did not manage to read shows a dash — never a plausible number standing in for one.

This page reads. It does not act.

It never asks you to sign anything, never requests an approval, and never builds a transaction. Opening a position, closing one and approving a token all happen somewhere else — not here, and not on this domain.

The reason is specific to this site and worth saying plainly: no page here sends a Content-Security-Policy header, and the home page loads a third-party 3D library from a CDN with no integrity check. That is survivable while every page only reads. It stops being survivable the moment a page on this origin asks for a signature. So this one does not, and the restriction is enforced in code by a method allowlist that throws, not by this paragraph.

Where to read from, and whose positions

The address field is the whole point: this works with no wallet installed, and it reads any address you can name, including one that is not yours. The wallet button exists only so you do not have to copy your own address by hand — it calls eth_accounts, then eth_requestAccounts if the first returns nothing, and it calls nothing else, ever. The endpoint is editable because the default is a public one and public endpoints go down; three that answered chain id 0x89 on 2026-08-12 are listed at the bottom of this page.

The fee on a position — the ratified rule

The protocol is paid only if the position produced a result, and never if it closed below what went in. The check is price-free: it compares what comes out against what was deposited, token by token, so a fee is never charged on a position that shrank. A position with no deposit on record is charged nothing — an absent record is not a zero.

This page does not compute that fee. It reads what the position manager holds; the fee is settled where the position is closed. The rule is written here because it governs the thing you are looking at, and a rule you only meet at the moment it is charged is a rule you were not told.

N-1 · whose contract this is

TriviuLPVault is a shared router, not a vault per user. The position stays yours — the mint uses recipient msg.sender, and the contract is never ownerOf — but the router and its whitelist are shared with everyone else using it.

So the sentence "the contracts are yours" describes the arbitrage triad and does not describe the LP. That distinction is not decoration: it changes who can be affected by a change to the router, and it is why the row above reads balanceOf(vault) live instead of asking you to believe it.

What this page does not do

  • It does not open a position. There is no deposit path here.
  • It does not close a position and does not collect fees.
  • It does not ask for an approval, of any size, for any token.
  • It does not build calldata for a write, and never calls eth_sendTransaction.
  • It does not read a private key, a seed phrase or a password — it has no field for one.
  • It stores nothing: no cookie, no analytics, no server of its own. The address you type is held in the tab and goes only to the RPC endpoint shown in the form.
